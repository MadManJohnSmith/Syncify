## Bloqueos y cosas que NO se verificaron

1. **LY-12b / LY-12**: `src-tauri/src/commands/lyrics.rs` permite que el probe recupere letra embebida o sidecar después de Delete. Se necesita decidir si el borrado es duradero para esa pista, si borra también orígenes físicos, o si la recuperación gana; son políticas visibles diferentes. No se cambió ni la prueba de paridad para acallar el comportamiento.
2. **LOG-04 (solo política)**: ¿release debe escribir logs al disco por defecto? Hoy `false`, respetando el ajuste persistido si existe. Implica privacidad y consumo de disco; el bug de lectura persistida sí está reparado.
3. **PMS-02**: los 8 alias SQL calculan puntuaciones fijas distintas del motor/pesos de usuario. Falta acordar fórmula única y si se aplica a todos los SELECT. No se alteraron sin decisión.
4. **Diseños del triaje**: DSC-01 (vista Descargas), DSC-06 (acciones duplicadas), MET-02 (estadística MBID global), LY-06 (editor), LOG-01 y AQ-02 no tienen objetivo visual acordado. DSC-03 exige datos de una BD/runtime reales; LY-07 y LY-11 necesitan criterio de proveedores/migración. M-01 y L-06 sí fueron decididos el 2026-10-09 (Saved Migration Presets se conserva; Special se retira), y MET-03 ya tenía petición explícita y está implementado.
5. **Windows/MSVC**: falta SDK `lib.exe` para completar `cargo check -p syncify-tauri --target x86_64-pc-windows-msvc` en Linux. La comprobación de partes portables no equivale al target completo.
6. **MPRIS/GUI**: no se observó exposición real `org.mpris.MediaPlayer2.*` en D-Bus ni la ventana desaparecer al abrir un diálogo en una app real. Las pruebas de símbolos WebKitGTK y unitarias no equivalen a aceptación visual/manual.
7. **Red/credenciales y rendimiento real**: 9 tests Rust ignorados (red o datos externos); no se hicieron pruebas de carga de notificaciones (la cifra «100 popups» no estaba observada), ni pruebas live de sincronización remota bidireccional, watchers, escritura ID3 o cuenta por ítem. Las últimas son limitaciones de diseño/alcance, no afirmaciones de implementación.
8. **Herramienta `Skill` de ZCode**: la CLI descubre 23 skills sin diagnósticos; ZCode anuncia `Skill` y `ResolveWorkflowQuestion` en el request al proveedor, pero no las expone en este namespace de sesión. El reinicio de Desktop no lo reparó. No existe un ajuste de skills o un cambio de configuración del proyecto que lo remedie de forma soportada; se trata de una discrepancia de catálogo del cliente/harness que requiere reparación de ZCode. Ejecutar un workflow guardado por nombre no restaura `Skill`.

No se publicó release ni se afirmó que Windows/MSVC, MPRIS o GUI pasaran.
